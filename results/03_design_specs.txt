================================================================
  DESIGN SPECIFICATIONS  —  bmi_chip_top
  BMI Chip Digital Backend  |  Northwestern CE392
================================================================

----------------------------------------------------------------
  ARCHITECTURE OVERVIEW
----------------------------------------------------------------
  Type        : Fixed-latency batch-windowed neural classifier
  Function    : Classifies brain state from 8-channel neural
                recordings into 4 output classes

  Classes     : PG-LF  (Power Grasp, Low Freq)
                PG-HF  (Power Grasp, High Freq)
                SG-LF  (Skilled Grasp, Low Freq)
                SG-HF  (Skilled Grasp, High Freq)

  Pipeline    : ADC → Sample Collection → SBP Feature Extraction
                → MLP Inference → Argmax → SPI Output

----------------------------------------------------------------
  TOP-LEVEL PORTS
----------------------------------------------------------------
  clk          System clock  (2-10 MHz operating, 50 MHz target)
  rst_n        Active-low reset
  adc_sample   8-bit ADC input from SAR ADC
  adc_channel  3-bit MUX select output (drives 8:1 analog MUX)
  spi_sclk     SPI clock input (from external MCU/FPGA)
  spi_cs_n     SPI chip select (active low)
  spi_miso     SPI data output (classification result + scores)
  scan_en      Scan chain enable (weight loading at power-up)
  scan_clk     Scan chain clock
  scan_in      Scan chain data input

----------------------------------------------------------------
  BLOCK DETAILS
----------------------------------------------------------------

  1. SAMPLE COLLECTION
     Function : Drives 8:1 analog MUX, collects 8×250 samples
     Memory   : 16,000-bit register file (8ch × 250 × 8b)
     Latency  : 2,000 clock cycles per window
     Key sig  : window_ready — pulses when window is full

  2. SBP FEATURE EXTRACTION
     Function : Computes Spiking Band Power per channel
     Formula  : SBP[ch] = Σ|sample - 128| >> 8  (250 samples)
     Hardware : 1× 16-bit accumulator, 2× counters, small FSM
     Latency  : 2,001 clock cycles (8 channels × 250 samples + 1)
     No multipliers — only abs value and right shift

  3. MLP INFERENCE
     Network  : 8 → 8 (ReLU) → 4  fully-connected
     Weights  : 108 bytes, signed 8-bit quantized
                Loaded via 864-bit scan chain at power-up
     Hardware : 1 shared 32-bit MAC (time-multiplexed)
     Bias scaling: hidden=85, output=109 (from training pipeline)
     Latency  : ~110 clock cycles
     Outputs  : 4× signed 32-bit class scores

  4. ARGMAX
     Function : Finds index of maximum class score
     Hardware : 1-cycle comparison tree (4× 32-bit signed)
     Output   : 2-bit predicted class (0-3)

  5. OUTPUT FORMATTER
     Function : Assembles 10-byte SPI packet
     Packet   : [79:72]=0xAA sync | [71:64]=class
                [63:48]=score0 | [47:32]=score1
                [31:16]=score2 | [15:0] =score3

  6. SPI SLAVE
     Protocol : SPI Mode 0 (CPOL=0, CPHA=0)
     Width    : 80 bits (10 bytes)
     Features : 2-FF synchronizer for SCLK/CS_N
                Preloads shift register on CS assert
                packet_ready ACK restarts sample collection

----------------------------------------------------------------
  HANDSHAKE CHAIN
----------------------------------------------------------------
  window_ready  → sbp.start
  sbp.done      → mlp.start
  mlp.done      → argmax.scores_valid
  argmax.decision_valid → output_formatter
  packet_valid  → spi_slave (preload)
  packet_ready  → output_formatter (deassert) +
                  sample_collection.resume (restart)

----------------------------------------------------------------
  MLP WEIGHT LOADING (SCAN CHAIN)
----------------------------------------------------------------
  Total bits   : 864  (108 bytes)
  Layout       : hw[8][8]=64B | hb[8]=8B | ow[4][8]=32B | ob[4]=4B
  Clock        : scan_clk (separate from system clock, async)
  Timing       : Load weights while rst_n=0 to prevent spurious
                 ADC captures during the scan operation
